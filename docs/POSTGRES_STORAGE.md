# Хранение резюме в PostgreSQL

Решение D-005, 04.09.2026: приложение и PostgreSQL остаются на Railway,
Supabase Storage и его SDK больше не используются. Статические изображения сайта
остаются в `public`; новые функции загрузки изображений CMS этим изменением не добавляются.

## Сохранение и доступ

- `ResumeFile.content` — `bytea`; одна запись на отклик, максимум 10 МБ.
- Размер, MIME/расширение и бинарная сигнатура проверяются до записи; размер и MIME
  дополнительно ограничены SQL CHECK-constraints.
- Отклик, файл и счётчик вакансии записываются одной транзакцией. Повтор с тем же
  idempotency key не создаёт второй файл. Сбой транзакции откатывает все три изменения.
  Таймаут транзакции — 30 секунд: запись файла на границе 10 МБ может превышать
  стандартные 5 секунд Prisma. Граничный размер покрыт интеграционным тестом.
- Бинарное поле вынесено из `VacancyResponse`, поэтому списки/уведомления его не читают.
- `/api/admin/resumes/[id]` проверяет активность пользователя и разрешение `responses`
  до чтения байтов. Без сессии — 401, без права — 403, отсутствующий файл — 404.
- Скачивание идёт как attachment с безопасным UTF-8 filename, `nosniff` и
  `Cache-Control: private, no-store`. Знание URL не даёт доступа без текущих прав.
- Старое поле `resumeFilePath` сохранено; для новых файлов содержит ID `ResumeFile`.
  Физическое удаление отклика удаляет его файл через FK cascade. Архивация файл сохраняет.

## Миграция

`20260904090000_store_resumes_in_postgres` добавляет таблицу и ограничения без удаления
существующих заявок, пользователей, контента или столбцов. На Railway применяется
стандартной командой `pnpm db:deploy` в pre-deploy.

Если до обновления в БД есть ненулевые `resumeFilePath`, миграция намеренно останавливается:
сначала нужны защищённый экспорт внешних файлов, проверка количества/хешей и отдельная
миграция импорта. Нельзя обнулять ссылки или помечать миграцию применённой ради обхода
этой проверки. В текущем production Supabase не был настроен.

Не откатывайте production на версию с Supabase после появления новых файлов:
предпочтителен исправляющий forward-deploy, сохраняющий новый формат.

## Проверки и эксплуатация

Проверено 04.09.2026: 35 unit-тестов и 9 интеграционных тестов PostgreSQL прошли,
включая SHA-256 round-trip для 10 МБ, повторную/конкурентную отправку, откат при
ошибке CHECK и остановку миграции при старой внешней ссылке. Браузерная проверка
небольшого файла прошла сохранение и выявила таймаут для 10 МБ; исправление таймаута
подтверждено интеграционным тестом. Полный browser E2E после исправления ещё не повторён.

- `pnpm test -- --runInBand` — unit-тесты файлов, доступа и существующих сценариев.
- `$env:RUN_POSTGRES_INTEGRATION='1'; $env:NODE_OPTIONS='--experimental-vm-modules'; pnpm test -- --runInBand vacancy-response-postgres`
  — интеграционный тест на локальной БД из `POSTGRES_TEST_URL` (или `DATABASE_URL`).
  Флаг VM modules нужен Jest для ESM-компилятора Prisma 7. Создаёт и удаляет только
  свою временную схему; соединения с нелокальными хостами запрещены.
- Резервная копия PostgreSQL теперь включает резюме. Нужны backup/restore-проверки,
  контроль объёма БД и согласованная политика хранения ПДн. Автоматический backup
  не включается этим изменением.
- Не копируйте production-резюме в локальные тесты и не выводите байты, имена файлов,
  контакты или строки подключения в логи. Для smoke-тестов используйте синтетические данные.
