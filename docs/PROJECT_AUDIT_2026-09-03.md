## Блокеры до production

1. **Админ-панель отсутствует.** `/admin` возвращает 404. Нет auth/RBAC, просмотра заявок и откликов, CRUD новостей/вакансий/главной, пользователей и настроек уведомлений.
2. **Юридическая часть не утверждена.** Политика ПДн прямо обозначена как проект; BIZ-04 остаётся открытым. Сбор реальных персональных данных до согласования блокирован.
3. **Согласия на публикацию детских фото не подтверждены.** В публичной истории репозитория находятся идентифицируемые фотографии из `docs/img_instagram`. Простое удаление из текущей ветки не очистит Git history; нужна отдельная согласованная процедура и ротация публичного репозитория при необходимости.
4. **Миграции локальной БД не отмечены применёнными.** Prisma видит две неприменённые миграции, хотя схема была синхронизирована через `db push`. Перед staging нужен безопасный baseline/resolve и проверка `migrate deploy` без потери данных.
5. **Уведомления неполные.** Есть только Telegram; нет email fallback, durable queue/retry, ссылки на карточку в админке и управления настройками.

## Значимые оставшиеся проблемы

- Rate limit хранится в памяти одного Node-процесса, не подходит для serverless/нескольких инстансов и не имеет очистки.
- Ошибки БД на публичных страницах маскируются под пустой контент или 404; отдельного health/readiness endpoint нет.
- Для резюме нет антивирусной проверки. Legacy `.doc` можно определить только как общий CFB-контейнер без глубокого анализа содержимого.
- Cascade delete вакансии удаляет отклики; для рабочих данных нужна политика архивации/удержания.
- Seed допускает слабый placeholder-пароль и не ротирует существующий пароль администратора.
- Progressive enhancement форм неполный: без JavaScript POST не обработается server action; анкета без JavaScript не открывается.
- Нет integration/E2E-набора для БД, форм, Supabase, Telegram, авторизации и админки. Сейчас есть 8 unit-suite / 22 теста.
- `pnpm audit --prod` после обновлений: 0 critical, 10 high, 7 moderate, 1 low — остаток находится в транзитивных зависимостях и требует отдельного dependency-hardening прохода.
- CMS-изображения hero/новостей всё ещё выводятся через CSS `background-image`, без responsive `srcset` и оптимизации `next/image`.
- Новостям нужны собственные согласованные фотографии и кнопки «Поделиться»; сейчас сгенерированное изображение служит единым безопасным fallback.
- Вакансии работают через карточки и отдельные страницы, тогда как референс предполагает раскрытие/accordion прямо в списке.
- Текстовая часть логотипа пока набрана шрифтом интерфейса, а не оригинальным фирменным wordmark.
