# РАСтишка — подготовка staging

Этот репозиторий не содержит секретов. Аккаунты Railway, Telegram и Resend должны принадлежать организации; их создание и выдача прав требуют доступа владельца продукта.

## 1. Создать изолированные ресурсы

Создайте отдельные от production ресурсы:

- staging-окружение Railway с отдельным PostgreSQL и согласованным резервным копированием;
- staging-сервис приложения, использующий только эту БД;
- отдельный тестовый Telegram-чат и бот; не используйте личный чат сотрудника.

### Приватные файлы резюме

Резюме хранятся в PostgreSQL, таблица `ResumeFile`, поле `content` (`bytea`). Допустимые форматы: PDF, DOC, DOCX, JPG и PNG; максимальный размер — 10 МБ. Отдельный bucket и Storage-ключи не нужны.

Файл и отклик сохраняются одной транзакцией. Скачивание `/api/admin/resumes/[id]` проверяет активную сессию и права на отклики при каждом запросе и запрещает кэширование. Подробности и миграция: [POSTGRES_STORAGE.md](POSTGRES_STORAGE.md).

## 2. Внести секреты в staging environment

Ниже перечислены имена переменных. Значения задаются в настройках Railway или в локальном `.env`, но никогда не коммитятся.

| Группа | Обязательные переменные | Примечание |
| --- | --- | --- |
| БД | `DATABASE_URL`, `DIRECT_URL` | В Railway обе ссылки могут быть `${{Postgres.DATABASE_URL}}`. `DIRECT_URL` должен обходить внешний transaction pooler. `SHADOW_DATABASE_URL` нужен только для создания новых миграций в изолированной dev-среде. |
| Сайт | `NEXT_PUBLIC_SITE_URL`, `ADMIN_BASE_URL` | Указать staging-домен, например `https://staging.ras-tishka.kg`. |
| Auth | `AUTH_SECRET`, `AUTH_URL` | Секрет генерируется отдельно для staging и production. `NEXTAUTH_SECRET` и `NEXTAUTH_URL` поддерживаются для обратной совместимости. |
| Seed | `SEED_ADMIN_LOGIN`, `SEED_ADMIN_PASSWORD`, `SEED_ADMIN_NAME` | Пароль минимум 16 символов; передавать только через secrets manager. |
| Уведомления | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`; опционально `RESEND_API_KEY`, `NOTIFY_EMAIL_FROM` | До подключения канала переменные можно оставить пустыми. |

`NEXT_PUBLIC_*` переменные встраиваются в клиентский bundle при сборке. Никогда не добавляйте к ним токены, ключи и строки подключения.

## 3. Применить baseline и наполнить staging

```powershell
pnpm install --frozen-lockfile
pnpm db:deploy
pnpm db:seed
pnpm typecheck
pnpm lint
pnpm test --runInBand
pnpm build
```

Baseline `20260830170000_init` создаёт схему на пустой staging-БД. Нельзя применять `prisma migrate reset` к staging или production: это удалит данные.

Seed прекращает работу без заданного сильного пароля администратора. Контент-менеджер создаётся только при явной конфигурации его логина и пароля.

### Вход и роли админ-панели

После seed админ-панель доступна по `/admin/login`. Сессия хранится в подписанном JWT не более 8 часов.

- `ADMIN` имеет доступ ко всем разделам, настройкам уведомлений и пользователям.
- `CONTENT_MANAGER` управляет новостями, вакансиями и контентом сайта. Доступ к заявкам и откликам включается отдельными флагами в разделе «Пользователи».
- Резюме остаются приватными: доступ к файлу проверяется при каждом скачивании, включая отключение аккаунта и отзыв разрешения.
- Токен Telegram хранится только в environment secrets. В админке сохраняются включение канала и `chat_id`, там же доступен тест соединения и повтор неуспешной отправки.

## 4. Проверка готовности

- `pnpm exec prisma migrate status` показывает все три миграции, включая `20260904090000_store_resumes_in_postgres`, как применённые.
- `pnpm db:seed` создаёт только учётные записи, заданные в secrets manager, и тестовый контент только вне production.
- Сборка проходит с теми же public-переменными, которые будут использованы на staging.
- Логи Railway содержат структурированные события без паролей, токенов, телефонов, имён, содержимого файлов и данных ребёнка.
- Синтетическое резюме сохраняется/скачивается побайтово, а запрос без сессии получает 401.

## Передача в production

Production получает отдельные PostgreSQL/Auth/Telegram secrets и проверенный backup/restore. Локальные/staging-секреты не следует использовать как production-секреты. В Railway pre-deploy: `pnpm db:deploy && pnpm db:seed`; build: `pnpm build`; start: `pnpm start`; healthcheck: `/api/health`. Домены этим переходом не меняются.
